# Маркетолог: как это работает

Маркетолог раз в 30 минут анализирует **факты** (история чатов, членство, баны/муты, SpamBot)
и сам чинит то, что можно чинить безопасно. Для каждой пары «аккаунт × чат» — один диагноз.

| Что видим | Что делает сам | Когда зовёт человека |
|---|---|---|
| аккаунта нет в чате | вступает (invite / @username / гарант / капча), затем настраивает | нет ссылки вступления; автовступление не вышло 2 раза за сутки |
| в чате, отправка не настроена | настраивает | не получается 3 раза за сутки |
| настроено, но 3 часа ни одного сообщения | пересоздаёт очередь (до 2 раз в сутки) | не помогло (модерация удаляет / антиспам) |
| **мут** | читает срок, ждёт; после срока перепроверяет и продолжает; срок неизвестен — перепроверка каждые 3 ч | — |
| **бан в чате** | ничего: не вступает, не пишет, не ищет. Раз в неделю только читает статус — вдруг сняли | — |
| **SpamBlock** (лимит @SpamBot) | в закрытых по лимиту чатах не пишет; сначала пробует закрытые чаты (по 3 за цикл); где не уходит — закрывает пару до конца лимита; @SpamBot каждые 3 ч; лимит снят — возвращает все пары | аккаунт не пишет ни в один чат |
| не хватает аккаунтов для паузы ≤5 мин | — | пишет в чат: «нужно ещё ≈N новых аккаунтов» (считается только после учёта всего, что починит сама) |

Лимиты: кулдаун и максимум попыток в сутки на каждую пару и действие — бесконечных повторов нет.
Выключатель автопочинки: «Отчётность» → «Автофикс». Данные собираются раз в час (:07).

## Почему аккаунта нет в чате (вместо общего «не вступлен/недоступен»)

В отчётах и советах у каждой пары «аккаунт × чат» одна из причин:

| Причина | Что делает система |
|---|---|
| **бан** (вступление / вылет / отправка) | пишет «бан», больше не трогает, раз в неделю читает статус |
| **заявка отправлена** | ждёт одобрения админа, повтор через 72 ч |
| **спамблок + публичный чат** | вступит сама, когда снимется лимит (закрытые чаты по invite/гаранту вступает сразу) |
| **нет ссылки** (в каталоге только числовой id) | берёт `@username` / invite у любого своего аккаунта, который уже в чате (`GetFullChannel`, при правах — `ExportChatInvite`), и будит остальных; не вышло — просит вас добавить ссылку |
| **нужно вручную** (бот, особая капча) | просит человека |
| **сдался** (серия неудач) | пробует снова через `AUTOPILOT_ABANDONED_RETRY_HOURS` (72 ч), а не «никогда» |
| **пауза после неудачи** | следующая попытка по экспоненциальному бэкоффу |

Настройка расписания (`schedule`) у аккаунта, которого нет в чате, больше не сжигает попытки и не уходит
в «стоп до недели»: вступлением занимается автопилот и сразу после него настраивает отправку.

## Советник: польза против вреда

```
польза = клиентов за 7 дн. · 5 + отправок за 48 ч · 0,1 (не больше 60) + рабочих чатов · 0,5
вред   = банов · 2 + повторов спамблока · 2 + 3 (если ограничен сейчас) + мутов · 0,5
```

* **🛑 лучше отключить** — клиентов 0, вред ≥ `ADVISOR_MIN_HARM` (4) и вред больше пользы. Числа выводятся в сообщении.
* **Спамблок при включённом sender** — аккаунт не списываем: автопилот сам переводит его в **dead**
  (sender выключен, остаётся schedule, который работает в доступных чатах). Выключатель: `SPAM_AUTO_DEAD=false`.
* «Не в чате» не считается вредом: это отдельная строка с причиной (таблица выше).

## «Нужно ещё N аккаунтов»

Один аккаунт работает во всех чатах сразу (в каждом — раз в `interval` минут), поэтому число считается как
**дефицит самого «голодного» чата** (`max`, не сумма): `нужно в чате = ⌈interval / 5⌉`, дефицит = нужно − «могут писать».
В «могут писать» не входят: бан, спамблок, выключенные вручную, и аккаунты, которые **не могут вступить**
(спамблок при публичном чате, «сдался», нет ссылки). Замьюченные на известный срок показываются отдельно:
«если вернутся сами — хватит ≈M».

## Обновление Telethon

`TypeNotFoundError: Could not find a matching Constructor ID …` — Telegram сменил схему (новый `User`),
а Telethon 1.44 (layer 227) её не знает. Нужен `telethon>=1.45.0` (layer 229): `pip install -U telethon`
и перезапуск. Если версия старая, бот напишет об этом в лог при старте.
